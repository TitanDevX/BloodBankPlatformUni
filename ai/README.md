
# Blood Demand API — prototype

النموذج يتوقع طلب يوم واحد لكل زمرة، مع تجميع جميع المراكز والمستشفيات والمكونات. ليس توقعًا مستقلًا لكل بنك أو مكون، وليس توصية صرف أو مخزون آمن.

## التشغيل
استخدم إصدار Python المسجل في metadata.json، ثم افتح الطرفية داخل هذا المجلد:

```bash
python -m pip install -r requirements.txt
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

افتح http://127.0.0.1:8000/docs ثم POST /predict ثم Try it out، والصق محتوى example_request.json. GET /health يتحقق من تحميل النموذج.

## دمج قاعدة البيانات
يرسل التطبيق blood_type وprediction_date وقائمة history من سبعة سجلات: date وunits_requested. يجب أن تكون السجلات للزمرة نفسها، وبالنطاق نفسه الذي تدرب عليه النموذج، ولكل يوم من الأيام السبعة المكتملة السابقة مباشرة. لا ترسل أيامًا مفقودة كصفر إلا عندما يؤكد سجل كامل عدم وجود طلبات. لا ترسل سجلًا جزئيًا لليوم الجاري.

الأسماء الدقيقة والأعمدة محفوظة في metadata.json. day_of_week يستخدم الاثنين=0 والأحد=6؛ الحساب يتم داخل feature_builder.py. الطلب لا يحتاج وحدات اليوم المستقبلية. لا ترسل بيانات تاريخية تخص مستشفى واحد إلى نموذج متعلم من الإجمالي.

هذا تقييم one-day-ahead مع actual history، وليس توقع سبعة أيام مستقبلية دفعة واحدة. يجب تحديث الطلب الفعلي بعد اكتمال كل يوم. عندما تكون البيانات قديمة، يلزم سجل فعلي حديث مكتمل؛ مثال الطلب يستخدم اليوم التالي لآخر تاريخ في CSV ولا يدعي أنه توقع حديث.

## المخرجات
predicted_units قيمة عشرية غير سالبة. rounded_units تقريب للعرض فقط، وليس safety stock. قياسات Test تخص النموذج المحفوظ؛ لم يدخل Test في التدريب أو الاختيار. خفض MAE لا يضمن كفاية الأداء لكل زمرة.

## الملفات
blood_demand_model.joblib: Pipeline كاملة. metadata.json: تعريف النموذج والإصدارات والنطاق. feature_builder.py: ميزات مشتركة. app.py: FastAPI. requirements.txt: إصدارات بيئة التصدير. validation_metrics.csv وtest_metrics.csv: تقارير. test_predictions.csv: نتائج تفصيلية للفحص، وليست بيانات لازمة لتشغيل API.

يُحمّل ملف joblib الذي أنشأته أنت فقط. الخادم مربوط محليًا؛ إدارة المصادقة والصلاحيات والنشر وربط الواجهة مسؤولية التطبيق المستضيف. يلزم اختبار التكامل في بيئة صديقك قبل النشر.
